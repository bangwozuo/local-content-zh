# 使用示例 —— 发布日历与复审工作流

## 示例 1：国庆周排期 + 复审闸门（脚本实跑）

**输入**（`examples/input.json`）：2026-09-28 周、国庆节点（窗口 -2~+1）、6 条内容
（4 passed / 1 pending / 1 failed）。

**命令**：`python scripts/run_flow.py --input examples/input.json --outdir out`（退出码 0）

**输出**（实跑值）：4 条入历；节点内容 C2 落 10-01 正日子晚高峰而非窗口首日；
2 条被闸门拦下（pending/failed 各一），逐条给原因。
产物：`发布日历.xlsx`（三 sheet）/ `publish_calendar_flow.json`。

## 示例 2：内容全部 pending 的正确输出

**输入**：6 条内容 review_status 全为 pending。

**输出要点**：

| 项 | 结果 |
|---|---|
| 日历 | 空（全槽无内容），**不伪造排期** |
| 任务清单 | 6 条复审任务 + 各自待审要点（AI 标识/探店合作/划线价依据） |
| 禁止行为 | 不「先排上、发布前再审」——闸门在排期之前 |

## 示例 3：week_start 非周一的硬拒绝

**输入**：week_start = "2026-09-30"（周三）。

**行为**：报错「2026-09-30 是周三，week_start 必须是周一」，退出码非 0。
讲解：日历错位一周是排期类工具最贵的错误，硬校验比宽容解析更安全。

## 示例 4：槽位冲突的降级

**输入**：7 条高优先抖音内容挤一周（每平台每天 ≤1 条 → 抖音全周最多 7 槽，
但高优先互相争晚高峰）。

**输出要点**：晚高峰按优先级与 ID 序占位，落败者进午高峰；仍放不下的标
「本周槽位已满，未排入」+ 下周补排建议——不挤占已排内容，不悄悄丢内容。

## 整改前后对照（上一版 vs 本版）

| 维度 | 上一版 | 本版 |
|---|---|---|
| 排期 | 无真实排期逻辑 | 槽位规则（午晚高峰/周末/每平台每日 ≤1 条/优先级） |
| 节点 | 无 | 窗口映射 + 正日子/窗口标签 + 节点内容优先 |
| 复审 | 无 | 闸门前置：pending/failed 不入历 |
| 校验 | 无 | week_start 周一硬校验、空清单中止 |
| 产物 | 无 | 三 sheet Excel + JSON |
