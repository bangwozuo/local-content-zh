# 使用示例 —— 每日热点选题工作流

## 示例 1：成都火锅店日常选题（脚本实跑，完整流程）

**输入**（`examples/input.json`）：成都/火锅/6 条候选（含互动量、竞争度、匹配度、发布时长）。

**命令**：`python scripts/run_flow.py --input examples/input.json --outdir out`（退出码 0）

**输出**（实跑值）：

| 选题 | 级别/总分 | 发布建议 |
|---|---|---|
| 老板把毛肚免费续到凌晨2点的老店 | A 追（87.0） | 24h 内拍，次日午高峰 12:00 |
| 国庆去哪吃？成都火锅节10月1日开幕 | A 追（81.8） | 节点类提前 7-14 天 |
| 春熙路新开的市井火锅，排队2小时也要吃 | B 观察（61.6） | 次日复查，涨则拍 |

产物：`每日选题推送.docx`（37.7 KB）/ `选题评分明细.xlsx`（5.8 KB）/ `daily_topic_flow.json`（3.2 KB）。

**讲解**：七夕条实跑 71.9 分也够 A 级，但 Top3 只取 A 级前 2 + B 级第 1——
它进入「次日轮换候选」而非今天拍。淘汰名单如实展示这个取舍，不悄悄吞掉。

## 示例 2：全部候选都是 C 级（无必追选题的正确输出）

**输入**：候选 3 条，全是超 7 天老话题或红海话题。

**输出要点**：

| 项 | 结果 |
|---|---|
| 选题卡 | 输出 B 级择优（本例不足）→ 实际 0 张，标「本周无必追选题」 |
| 榜单 | 照常输出 3 条 C 级 + 淘汰原因 |
| 禁止行为 | 不强行抬级、不编造「备用选题」 |

## 示例 3：数据不全的降级执行

**输入**：候选 5 条，其中 2 条缺 heat_48h（用户只复制了标题）。

**输出要点**：

| 项 | 结果 |
|---|---|
| 处理 | 2 条标「数据不全」，不参与热度归一化，不估数补齐 |
| 评分 | 用其余 3 条归一化，输出中明确标注「3/5 条参与评分」 |
| 提示 | 列出缺失字段清单让用户补粘贴互动量 |

## 步骤失败处理演示

| 注入故障 | 实际行为 |
|---|---|
| candidates 为空 | 报错「S1 输入不能为空」，退出码非 0，不产出半成品文件 |
| 候选含竞争对手负面选题 | S2 拒出卡并标注原因（按 prompt 规则，模型执行） |
| B 级选题次日互动量跌 40% | 按流程降 C，不进拍摄（人工复查环节执行） |

## 整改前后对照（上一版 vs 本版）

| 维度 | 上一版 | 本版 |
|---|---|---|
| 执行结果 | 「无法抓取实时数据」+ 3 条推测选题 | 真实候选评分 → 选题卡 → 人工确认点 |
| DAG | 单节点直通 | 双技能 + A 级分支判断 + 人工确认节点 |
| 失败处理 | 一句「记录错误并中止」 | 每步具体失败分支（数据不全/全 C/负面选题/掉档） |
| 产物 | 无 | Word 选题推送 + Excel 明细 + JSON |
