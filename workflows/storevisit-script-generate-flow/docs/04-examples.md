# 使用示例 —— 探店脚本生成工作流

## 示例 1：火锅店 60s 全流程通过（脚本实跑）

**输入**（`examples/input.json`）：9 镜分镜草案、三平台标题、付费挂车文案（含「探店合作」）。

**命令**：`python scripts/run_flow.py --input examples/input.json --outdir out`（退出码 0）

**输出**（实跑值）：合计 60s、语速 4.4-5.5 字/秒全达标、标题 15/18/15 字全合规、
合规零红线，1 条 🔵（AI 写稿开声明）→ **可进人工终审**。
产物：`拍摄脚本包.docx` / `分镜校验表.xlsx` / `storevisit_flow.json`。

## 示例 2：语速超差与黄金 3 秒被吃（返工路径演示）

**输入**：首镜 6s、钩子台词 22 字；镜头 7 为 8s 64 字。

**输出要点**：

| 问题 | 脚本输出 |
|---|---|
| 首镜 6s > 3s | 「首镜头 6s > 3s：黄金3秒必须给钩子，压缩首镜或换钩子画面」 |
| 钩子 22 字 > 15 字 | 「钩子台词 22 字 > 15 字上限，3 秒内念不完」 |
| 镜头 7 语速 8.0 | 「8.0 字/秒超上限，减 13 字或延时长」（给出具体数字） |
| 判定 | 打回重改（红线计数按 S3 单独算；S1 问题进返工清单） |

**讲解**：三条问题都给了可执行数字（减几字、压几秒），不是「节奏再快点」这类空话。

## 示例 3：文案带红线（S3 拦截演示）

**输入**：文案改为「这家是我吃过最好吃的火锅！加微信进粉丝群领优惠」，
business_type=付费挂车、文案中无「探店合作」。

**输出要点**：

| 级别 | 命中 |
|---|---|
| 🔴 | 极限词「最好」（《广告法》第九条） |
| 🔴 | 站外导流「加微信」 |
| 🔴 | 探店合作标注缺失（《互联网广告管理办法》第 9 条） |
| 判定 | **打回重改**（红线 3 > 0），逐条给整改动作后重扫 |

## 示例 4：shots 为空的正确中止

**输入**：只给门店 brief 不给分镜草案。

**行为**：报错「shots 为空：S1 需要分镜草案，不能为空」，退出码非 0，
不产出半成品校验表——避免「看起来跑完、实际没校验」的假完成。

## 整改前后对照（上一版 vs 本版）

| 维度 | 上一版 | 本版 |
|---|---|---|
| DAG | 单节点直通 | 三技能 + 两个判断闸门（配平/红线） |
| 校验 | 无 | 时长配平、语速 ±20%、首镜 3s、标题字数、词表扫描（全部量化） |
| 失败处理 | 「记录错误并中止」一句 | 每步具体分支 + 具体整改数字 |
| 产物 | 无 | Word 脚本包 + Excel 三 sheet 校验表 + JSON |
