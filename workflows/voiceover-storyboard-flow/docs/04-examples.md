# 使用示例 —— 口播文案+分镜工作流

## 示例 1：烘焙店 45s 逐字稿对稿（脚本实跑）

**输入**（`examples/input.json`）：5 段逐字稿、目标 45s、抖音+小红书。

**命令**：`python scripts/run_flow.py --input examples/input.json --outdir out`（退出码 0）

**输出**（实跑值）：五段占比全部达标；抓出 2 个真问题——
钩子 18 字 > 15 字（🔴 3 秒念不完）、引导段 2.22 字/秒台词过稀（🟡 9s 应念约 27 字）。
场景段 2.87 字/秒未误报——B-roll 留白合法。
产物：`分镜口播校验表.xlsx` / `分镜时长分布.png` / `voiceover_flow.json`。

**讲解**：钩子 18 字按 6 字/秒的极速语速勉强能塞进 3 秒，但实拍一定吃字——
所以规则卡 15 字上限而不是卡语速上限，这是拍过的人才懂的差别。

## 示例 2：60s 火锅稿全通过

**输入**：五段 3/22/20/10/5s，台词 14/108/98/48/22 字（总 290 字）。

**输出要点**：合计 60s；语速 4.7/4.9/4.9/4.8/4.4 全达标；
占比偏差 0/0/0/0/0s；平台抖音 ≤60s ✅ → **通过**，直接进人工对稿。

## 示例 3：时间轴有洞的正确抓法

**输入**：五段时长 3/20/18/10/5s，目标 60s。

**输出要点**：

| 项 | 结果 |
|---|---|
| 时间轴 | 逐段累加合计 56s ≠ 60s（±2s 容差外） |
| 问题 | 「时间轴合计 56s ≠ 目标 60s（允许 ±2s）」——剪辑会出 4s 黑场或静音 |
| 整改 | 场景段 +2s、亮点段 +2s（或目标改 56s 重跑） |

## 示例 4：B-roll 留白不误报（假阳性拦截验证）

**输入**：场景段 15s 只有 30 字台词（2.0 字/秒）。

**行为**：✅「B-roll 留白正常（场景/亮点段允许）」——探店视频靠画面撑节奏，
全片按 5 字/秒死算会把一半好段落误杀；只有钩子/引导/互动三段卡 2.5 字/秒下限。

## 整改前后对照（上一版 vs 本版）

| 维度 | 上一版 | 本版 |
|---|---|---|
| 校验 | 无（只生成不校验） | 字数实数/语速/时间轴/占比四道量化检查 |
| 台词计数 | 无 | 脚本按汉字实数，标点不计 |
| 留白处理 | 无 | 场景亮点段 B-roll 合法，口播必需段独立卡下限 |
| 占比 | 无 | 60s 基准预算按目标等比缩放 ±3s |
| 产物 | 无 | Excel 三 sheet + PNG + JSON |
