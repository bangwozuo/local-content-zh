# 使用示例 —— 本地热点追踪

## 示例 1：成都火锅店 · 周选题评估（脚本实跑）

**输入**（`examples/input.json`）：城市=成都，品类=火锅，8 条候选热点（含热度、竞争度、匹配度、发布时长）。

**命令**：

```bash
python scripts/hotspot_track.py --input examples/input.json --outdir out
```

**实跑结果**（退出码 0）：

| # | 选题 | 总分 | 级别 | 备注 |
|---|---|---|---|---|
| 1 | 老板把毛肚免费续到凌晨2点的老店 | 81.0 | A 追 | 低竞争（同类仅 8 条）+ 高匹配 + 6h 新热点 |
| 2 | 国庆去哪吃？成都火锅节10月1日开幕 | 75.6 | A 追 | 节点类，提前布局 |
| 3 | 七夕火锅店情侣套餐预订火了 | 68.4 | B 观察 | 节点类，提前布局 |
| 4 | 玉林巷子里人均50的苍蝇馆子火锅 | 56.8 | B 观察 | 次日复查热度 |
| 5 | 春熙路新开的市井火锅，排队2小时也要吃 | 54.9 | C 放弃 | 同类视频 260 条，红海 |
| 8 | 上个月爆火的旋转火锅现在凉凉了 | 9.2 | C 淘汰 | 超 7 天 |

**讲解**：春熙路条互动量 12.8 万看似很香，但同城已拍 260 条、竞争度 0 分，总分掉到 C——
这正是"跟拍热点"和"抢窗口期"的区别。淘汰说明里逐条给出了原因。

## 示例 2：拿不到实时数据时的降级用法

**输入**：

```json
{
  "city": "长沙",
  "category": "烘焙",
  "candidates": [
    {"title": "五一广场新开的碱水面包专门店", "source": "小红书本地生活",
     "heat_48h": 45000, "same_city_videos": 11, "match": 0.85, "hours_since": 18},
    {"title": "中秋流心奶黄月饼评测", "source": "节点日历",
     "heat_48h": 62000, "same_city_videos": 40, "match": 0.9, "hours_since": 72}
  ]
}
```

**输出要点**：碱水面包条（低竞争 + 开业 18h 内）判 A 追，建议 24h 内探店；
月饼条为节点类不衰减，但需提前 7-14 天布局并注明「节点类，提前布局」。

## 示例 3：假阳性拦截

**输入**：候选里混进「暴雨天躲进火锅店的人都在拍这一幕」（21 万互动、同类 900 条）与
「某网红店顾客与店员冲突」（负面舆情）。

**输出要点**：

| 候选 | 处理 | 原因 |
|---|---|---|
| 暴雨天躲进火锅店 | C 放弃 + 备注疑似红海 | 天气突发流量，同类视频 >200 条竞争度 0 分，匹配度低 |
| 网红店冲突视频 | 直接剔除，不进打分 | 蹭对手/同行翻车流量有法律风险，属 prompt 禁止项 |

## 整改前后对照（上一版 vs 本版）

| 维度 | 上一版 | 本版 |
|---|---|---|
| 输出 | 「无法获取实时数据」+ 3 条推测性选题 | 真实候选打分排序，A/B/C 分级 + 淘汰说明 |
| 方法 | 无 | 三因子加权公式 + 48h 半衰 + 节点豁免 |
| 产物 | 无 | Excel 选题榜 / PNG 得分图 / JSON |
| 数据缺失时 | 编了 3 条"基于规律推测"的选题 | 列清单让用户粘贴热榜条目，不编造 |
