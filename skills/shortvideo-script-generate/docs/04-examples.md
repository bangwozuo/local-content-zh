# 使用示例 —— 短视频脚本生成

## 示例 1：60 秒抖音探店（火锅店，完整流程）

**输入**（`examples/input.json`）：玉林陈记老火锅 / 火锅 / 毛肚现撕、牛油续锅、人均 65 /
团购 88 元双人餐（菜单价 176 元）/ 60s / 抖音。

**输出要点**（完整版见 `examples/output.md`）：

| 项 | 内容 |
|---|---|
| 钩子 A（推荐） | 「人均 65，毛肚管够的老火锅我找到了」价格反差型，首镜头毛肚特写 |
| 钩子 B | 「这一勺红油，等了 30 分钟」过程展示型，120fps 浇牛油慢动作 |
| 钩子 C | 「玉林巷子里为什么这口锅天天翻台？」提问式 |
| 口播 | 296 字（4.9 字/秒），五段 3+22+20+10+5 秒 |
| 分镜 | 9 个镜头，六字段齐全，时长合计 60s |
| 自查 | 价格有出处、划线价依据留存、无极限词、45-55s 标注「探店合作」 |

## 示例 2：45 秒小红书版（烘焙店）

**输入**：

```json
{
  "store_name": "巷口面包研究所",
  "category": "烘焙",
  "highlights": ["碱水面包每天 14 点出炉", "黄油用发酵黄油", "人均 22 元"],
  "price_per_head": 22,
  "duration_s": 45,
  "platform": "小红书"
}
```

**输出要点**：口播按 200-240 字预算压缩；钩子改「14 点准时出炉的碱水包，去晚只能闻香味」
（稀缺型，出炉时间是店家确认过的真实信息）；分镜增加出炉瞬间蒸汽镜头；
结尾互动改为「收藏这家店，周末去排队」——适配小红书收藏行为高于评论行为的特点。

## 示例 3：信息不全时的正确拒绝

**输入**：只给了店名和「东西好吃环境不错」，没有人均价、没有亮点细节。

**正确行为**：不编造。返回待补清单——

| 缺失字段 | 用途 | 建议补充方式 |
|---|---|---|
| 人均价 | 25-45s 段价格锚点 | 看结账小票或菜单区间 |
| 招牌菜 2-3 道 | 3-25s B-roll 主角 | 问店家销量前二 + 自己点单验证 |
| 团购套餐与依据 | 45-55s 段 | 套餐价 + 菜单原价截图 |
| 排队情况 | 稀缺型钩子（可选） | 实拍取号小票，不可口述编造 |

**整改前后对照（上一版 vs 本版）**

| 维度 | 上一版 | 本版 |
|---|---|---|
| 结构 | 无时段结构，一段口播到底 | 五段式各段有时长与字数预算 |
| 钩子 | 「今天带大家探一家店」 | 3 个不同类型钩子供 A/B，附留人逻辑 |
| 分镜 | 「拍毛肚」这类笼统描述 | 景别/运镜/画面动作/收音六字段 |
| 自查 | 无 | 完播红线、字数预算、价格出处逐项核对 |
